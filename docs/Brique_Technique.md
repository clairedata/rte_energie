## 🔍 Détail par Sous-Package Python (`src/rte_energy/`) & Front-End

### 📁 1. Sous-Package `db/` (Persistance & Schéma)
- **`connection.py` :** Fournit la fonction `get_db_connection()` réutilisée partout pour se connecter à PostgreSQL avec encodage UTF-8.
- **`init_schema.py` :** Contient les requêtes DDL (`CREATE TABLE IF NOT EXISTS`) pour créer `consumption_forecast`, `weather` et `model_forecasts`. Intègre également la fonction `verify_database()` qui affiche la volumétrie en base.

### 📁 2. Sous-Package `ingestion/` (Collecte Externe)
- **`rte_client.py` :** Interroge l'API RTE France en OAuth2. Transforme le payload JSON en lignes normalisées et fait un `execute_values` avec `ON CONFLICT DO UPDATE`.
- **`weather_client.py` :** Interroge l'API Open-Meteo pour récupérer la température et le vent au pas horaire.
- **`history_loader.py` :** Script de rattrapage par blocs de 7 jours pour ingérer un mois complet d'historique RTE.

### 📁 3. Sous-Package `training/` (Data Science & Expérimentations)
- **`eda.py` :** Analyse exploratoire de la consommation (moyenne, extrêmes) et tracé de la série temporelle.
- **`baseline.py` :** Implémentation du modèle naïf saisonnier (J-1) servant de référence absolue avec métriques MAE, RMSE, MAPE, WAPE.
- **`chronos_dataset.py` :** Découpe la série temporelle en tenseurs PyTorch de fenêtres glissantes (`context=512`, `prediction=64`).
- **`chronos_finetune.py` :** Boucle d'entraînement PyTorch supervisée avec l'optimiseur AdamW et la perte quantile native pour créer le modèle champion adapté au réseau français.
- **`chronos_benchmark.py` :** Benchmark à 3 voies comparant la Baseline, Chronos Zero-Shot et Chronos Fine-Tuned.
- **`lgbm_model.py` :** Modèle Machine Learning tabulaire multivarié combinant la consommation, les variables météo, les lags et les variables calendaires.

### 📁 4. Sous-Package `production/` (Services Opérationnels)
- **`predict.py` :** Service d'inférence autonome qui charge le modèle champion, extrait les données récentes, calcule les prévisions futures (96 pas de 15 min avec quantiles $q_{10}$, $q_{50}$, $q_{90}$) et les enregistre dans PostgreSQL.
- **`pipeline.py` :** Orchestrateur principal qui enchaîne automatiquement : Ingestion RTE ➡️ Ingestion Météo ➡️ dbt run ➡️ Inférence predict.py.

### 📁 5. Sous-Package `api/` & Application `frontend/` (Restitution Web React éCO2mix)
- **`src/rte_energy/api/app.py` :** API REST haute performance (FastAPI) exposant les endpoints `/api/status`, `/api/kpi`, `/api/consumption/history`, `/api/consumption/forecasts` et `/api/benchmark`, et servant le bundle React compilé (`frontend/dist`).
- **`frontend/src/App.tsx` :** Composant racine orchestrant les appels REST asynchrones, le filtrage temporel (24h/48h/7j) et l'auto-refresh toutes les 60 secondes.
- **`frontend/src/components/Header.tsx` :** En-tête éCO2mix avec voyant vert live clignotant, horodatage de synchronisation et bouton d'actualisation.
- **`frontend/src/components/KpiGrid.tsx` & `KpiCard.tsx` :** Cartes de synthèse temps réel (Puissance appelée, Pic, Creux, Météo/Thermosensibilité).
- **`frontend/src/components/ChartSection.tsx` :** Master timeline Chart.js reliant la consommation réelle et les prévisions avec intervalle de confiance 80% et filtres de séries.
- **`frontend/src/components/ThermosensitivityCard.tsx` :** Encadré pédagogique éCO2mix sur l'impact de la thermosensibilité (~2 400 MW/°C sous 15°C).
- **`frontend/src/components/BenchmarkTable.tsx` :** Tableau comparatif officiel de précision des modèles (MAE, WAPE, badges).
- **`frontend/src/index.css` :** Design System complet Vanilla CSS en Dark Mode Technologique (bleu électrique `#0072ce`, cyan `#00b4d8`, néon, glassmorphism, responsive).
